## Key Decisions

### 1. Type Checking Delegation
**Decision**: ts-forge will not own type checking. Users rely on IDE integration (tsserver) and explicit `tsc --noEmit` runs.

**Rationale**:
- Avoids reimplementing complex type checking logic
- Leverages existing developer workflows
- Reduces scope and maintenance burden
- Type checking is orthogonal to multi-target builds

### 2. VS Code Extension Architecture
**Decision**: Build lightweight extension complementing tsserver rather than custom language server.

**Rationale**:
- Lower complexity and maintenance
- Reuses existing TypeScript language features
- Focused on ts-forge-specific features (targets, config, build tasks)
- See ADR-001 for full details

### 3. Workspace Paths Injection Strategy
**Decision**: 3-layer approach with runtime injection during compilation rather than tsconfig.json modification.

**Rationale**:
- Preserves original tsconfig.json for IDE (no file churn)
- Allows per-target path resolution customization
- Enables build-time import rewriting without affecting development experience

### 4. Import Transformation Approach
**Decision**: Regex-based post-compilation transformation for v1.

**Rationale**:
- Simpler implementation than AST parsing
- Handles 95% of real-world cases
- Known limitations documented (no computed imports, template literals)
- Can upgrade to AST-based approach in v2 if needed

### 5. Topological Sort for Build Ordering
**Decision**: Kahn's algorithm for dependency-ordered builds.

**Rationale**:
- Standard algorithm for DAG topological sort
- Efficient O(V+E) complexity
- Detects circular dependencies
- Enables future parallelization (build independent packages concurrently)

## Challenges Encountered

### TypeScript rootDir Constraint (BLOCKING)

**Problem**: When workspace paths resolve imports outside a package's `rootDir`, TypeScript fails:
```
error TS6059: File '/path/to/workspace/packages/core/src/index.ts' is not under 'rootDir' '/path/to/workspace/packages/app/src'
```

**Root Cause**: TypeScript's `rootDir` constraint ensures output directory structure mirrors source structure. Cross-package imports violate this assumption.

**Context**: This is the core problem described in the architecture doc - existing tools don't handle workspace imports in multi-target scenarios.

**In Progress Solution**:
- Widen `rootDir` to workspace root when workspace paths are detected
- Requires careful handling of output paths to maintain package isolation
- Alternative: Pre-transform source files before compilation (more complex)

**Status**: Active implementation at session end. Build works for single-package scenarios; cross-package imports need rootDir fix.

## Architectural Notes

### Compiler Option Override Pattern
The tsc adapter uses a clean override pattern:
```typescript
const overrides = {
  module: target.module,
  moduleResolution: ts.ModuleResolutionKind.Bundler,
  outDir: path.join(pkgPath, target.outDir),
  declaration: true,
  paths: workspacePaths
};
```

This allows per-target customization while preserving the base tsconfig.json for IDE usage.

### Topological Sort Implementation
Using Kahn's algorithm provides:
- Deterministic build order
- Cycle detection (circular dependency errors)
- Foundation for future parallelization (track in-degree = 0 nodes)

### Import Transformation Limitations
Current regex-based approach has known limitations:
- No support for computed imports: `import(variable)`
- No support for template literals: `import(\`@scope/\${pkg}\`)`
- No support for dynamic require: `require(variable)`

These are edge cases (< 5% of real usage). Can be addressed in v2 with AST-based transformation if needed.

### Declaration Map Transformation
Declaration maps need three transformations:
1. Rewrite `sourceRoot` to maintain relative path correctness
2. Rewrite `sources` array entries for cross-package references
3. Accept minor column offset inaccuracy (character positions in transformed imports)

Column offsets are acceptable for v1 - Go-to-Definition will work, just potentially a few characters off.
