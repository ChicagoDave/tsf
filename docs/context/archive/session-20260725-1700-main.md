Skips the `npm whoami` gate for dry runs and when OIDC trusted publishing is detected via `env.ACTIONS_ID_TOKEN_REQUEST_URL` (set by GitHub Actions only when the job grants `id-token: write`), logging `"OIDC credentials detected — skipping npm whoami check"`. ## Key Decisions

### 1. OIDC detection is env-var-based, not a CLI flag
Detect via `process.env.ACTIONS_ID_TOKEN_REQUEST_URL` rather than adding a new `tsf publish` flag. This matches Sharpee's proposal (`npm-ci.md` Part A1) exactly and requires zero changes to how Sharpee's workflow invokes `tsf publish` — the var is already present whenever the job grants `id-token: write`.

### 2. No real-path OIDC test in this repo
The unit tests cover branch logic only (env var present/absent); the end-to-end proof of OIDC auth working is Sharpee's own Part D dry-run workflow, which is that proposal's gate, not this repo's. Noted as a risk in the plan rather than deferred silently.
