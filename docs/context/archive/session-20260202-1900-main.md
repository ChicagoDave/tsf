# Session: npm build fix for real-world monorepo (sharpee)

**Date:** 2026-02-02 19:00
**Branch:** main

## Problem

`tsf build --npm` failed on the sharpee monorepo (21 packages). All packages downstream of `@sharpee/core` got TS2307 "Cannot find module" errors because tsc couldn't resolve workspace package type declarations during the npm/staging build.

## Root Causes (Multiple)

### 1. No type resolution for npm builds (`src/compilers/tsc.ts`)
The npm target intentionally skipped tsconfig `paths` injection so tsc would emit bare specifiers for the import transformer to rewrite. But without paths, tsc couldn't find type declarations for upstream workspace deps since pnpm symlinks pointed at source packages whose `package.json` referenced `dist-npm/` (which didn't exist).

**Fix:** For `imports: 'relative'` builds with a staging dir, inject tsconfig `paths` pointing at already-compiled `.d.ts` files in the staging directory. Passes `npmStagingDir` through `CompileFn` type, `buildPackageTarget()`, and into `compile()`. Paths are relative to `baseUrl` (pkg.path) since tsc resolves paths relative to baseUrl.

### 2. rootDir `./src` not normalized (`src/compilers/tsc.ts`, `src/transform/imports.ts`, `src/transform/declarations.ts`)
`getOutputEntryPoint()` read `rootDir` from tsconfig (e.g. `"./src"`) but didn't strip the leading `./`, so `src/index.ts` didn't match the `./src/` prefix, producing wrong staging paths like `.../core/src/index.d.ts` instead of `.../core/index.d.ts`.

**Fix:** Added `rootDir = rootDir.replace(/^\.\//, '')` in all three copies of `getOutputEntryPoint()`.

### 3. Wrong dep outDir in transform steps (`src/transform/imports.ts`, `src/transform/declarations.ts`)
`rewriteSpecifier()` computed each dep's output dir as `path.resolve(depPkg.path, target.config.outDir!)`. For npm builds, `outDir` is an absolute staging path specific to the *current* package (e.g. `~/.tsf-publish/sharpee/stdlib`), not the dep. This caused stdlib's `.d.ts` to get `../src/index` (self-referencing) instead of a correct cross-package path.

**Fix:** When `outDir` is absolute, derive the dep's staging dir by replacing the package name segment: `path.join(path.dirname(currentOutDir), depPkg.name.replace(/^@.*\//, ''))`.

### 4. Broken self-referencing .d.ts paths (`src/compilers/tsc.ts`)
tsc occasionally emits relative paths in `.d.ts` files that include the rootDir segment (e.g. `../src/index`) which doesn't exist in the output after rootDir stripping.

**Fix:** Added `fixBrokenRelativeImports()` that walks output files, resolves each relative import, and if the target doesn't exist, tries removing intermediate path segments to find a valid target. Replaces the old regex-based `fixFlattenedImports()`.

### 5. Workspace deps stripped from publish manifest (`src/sync/package-json.ts`)
`generatePublishManifest()` deleted all `workspace:*` dependencies. With relative imports, the dep packages still need to be installed as npm dependencies so the `node_modules/@scope/` directory structure exists for relative paths to resolve.

**Fix:** Added `resolveWorkspaceDeps()` that converts `workspace:*` to `^<version>`, `workspace:^` to `^<version>`, `workspace:~` to `~<version>` using actual versions from the workspace packages map. Updated `generatePublishManifest()` to accept `workspacePackages` parameter.

## Key Debugging Insight

The `../src/index` broken path in stdlib's `.d.ts` was not emitted by tsc — tsc correctly emitted bare `@sharpee/world-model` specifiers. The broken path was *introduced* by `transformDeclarations` using the wrong outDir for dependency resolution. This was confirmed by adding a temporary debug log between tsc emit and transform steps.

## Test Results

All 90 tests pass. The sharpee monorepo npm build succeeds for all 21 packages with correct staging output and publish manifests containing resolved workspace dependency versions.
