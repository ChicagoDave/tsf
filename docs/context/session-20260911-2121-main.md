## Key Decisions

### 1. Validate the staged manifest against the staging directory, not the source tree
`tsf validate` checks the SOURCE manifest against the SOURCE tree, where `./dist/...` targets genuinely exist — it structurally cannot catch a broken staged manifest. The new gate lives in the publish path and validates the staged manifest against its own staging directory instead.

### 2. Extract, don't duplicate, the existence-check logic
`validateManifestTargets` is shared by the source-tree and staged-tree validators so the two checks can't drift apart as the manifest shape evolves.

### 3. The two REAL-PATH tests deliberately assert differently
The rejection test deletes a real staged entry point and asserts exit code 1, the gate's stderr, and that no `.tgz` was left in staging (proving packing never ran). Its "gate cleared" sibling does not assert exit code 0, because that run continues into real `npm pack`/`npm publish --dry-run` and asserting 0 would make the test depend on a reachable npm registry.
